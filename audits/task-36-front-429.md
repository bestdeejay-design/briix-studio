# Поставка: #36 (часть без решения владельца) — честная карточка при фронтовом 429 вместо «Очередь заполнена»

**Ветка:** `work/36-front-429-honesty` · **База:** `main` (b954e33)
**Задача:** briix-studio#36, инцидент 21.11. Из критериев инцидента, НЕ требующих
решения владельца: «честное сообщение UI „сервер недоступен“ вместо „очередь
заполнена“ — код 429 от фронта сейчас маппится в queue_full, вводит в заблуждение».
Фолбэк-политика (варианты 1–3 из issue) и мониторинг хоста — вне этой поставки,
ждут слова владельца.

## Корень

Клиентский `request()` (studio.js) любой HTTP 429 называл «Очередь сервера
заполнена». Но 429 на проде отдают ДВА разных источника:

- **bff** — настоящая очередь: JSON-конверт `{error:{code:'queue_full',…}}`
  + `Retry-After: 30` (bff.py, очередь джобов);
- **фронт хоста при деградации** (инцидент 21.11: хост 213.208.164.180 флапал,
  владелец поймал 429 от фронта при пустой очереди bff) — тело пустое или HTML.

Инцидент-репорт: «Владелец при первом прогоне получил „Очередь сервера
заполнена“ (HTTP 429 от фронта) перед этим — вероятный симптом деградации того
же хоста, а не реальная очередь (лог bff чист, cap 8, в момент ошибки 1 джоба)».
Пользователь получал ложный диагноз «очередь заполнена» от умирающего хоста.

## Фикс (studio.js)

- `request()`: на 429 тело парсится. «Очередь заполнена» — только когда это
  **подтвердил сам bff** (конверт `code:'queue_full'`). 429 без конверта →
  новый код **`server_busy`**: заголовок «Сервер перегружен», текст
  «Сервер перегружен или временно недоступен. Попробуйте ещё раз через
  минуту.» `Retry-After`, если фронт его прислал, сохраняется.
- `errorTitle()`: `server_busy` → «Сервер перегружен» (F-55: тип неполадки в
  заголовке, не всё «Ошибка»).
- 503-путь не менялся (`unavailable`, как было).

Покрытые пути: продюсер (`prepareMusic` → `chatNonStream`), чат-наставники
(SSE и не-стрим), генерация (`createMusic` → POST /jobs), поллинг джобов
(`server_busy` транзиентен, ретраится тем же механизмом T-14 — до 5 сбоев
с бэкоффом). Скачивание файлов имеет собственный честный путь
(`rate_limited`, не тронут).

Побочный эффект: mock поллинга в тестах (`pollFailures: [429, 503]` с конвертом
`{error:{code:'busy'}}`) теперь маппится в `server_busy`, а не queue_full:
поведение ретрая то же (транзиент), тест T-14 остался зелёным.
