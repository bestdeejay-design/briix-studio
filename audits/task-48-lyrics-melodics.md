## Диагноз: чего не хватало лирике

Конструктив (#47) закрыл динамику секций — но сам текст песни оставался вне
механик. Три дыры, все из библиотеки знаний:

1. **Десинк-гарда не была реализована.** Находка «Тысячи окон» (подтверждена
   финалом серии) прямо требует от мозга: RU + быстрый темп — предупредить
   владельца, предложить EN-лирику или замедление, «не выдавать такой результат
   молча». Студия молчала.
2. **Слоговой профиль не существовал.** RESEARCH_PACK: число слогов помогает
   сравнивать парные фразы при повторном использовании мелодии (куплет 1 ↔
   куплет 2, припев ↔ припев) — но сравнивать было нечем: RU-текст вообще
   не анализировался (английская эвристика его отвергала), парность секций
   не проверялась.
3. **Автолирика писалась без мелодических правил.** Промт автора песен не знал
   ни про дословный повтор припева (хук), ни про парность куплетов — модель
   могла выдать три разных припева, и мелодия «гуляла» между секциями.

## Принцип этапа (слово владельца)

Справки = **механики обогащения**, не прямые инструкции и не копирование лирик.
Поэтому всё сделанное — детерминированные проверки и направление генерации;
ни одна строка чужой лирики не попадает в треки, лирика пользователя не
переписывается никогда (только мягкие предупреждения), автолирика получает
правила ФОРМЫ, а не готовые тексты.

## Что сделано

### 1. Лирик-мозг v2 (`studio/lyrics-brain.js`, `2026-11-23-lyrics-1`)

Модуль из исследовательского стал продакшн-подключённым (index.html, до
studio.js; сюита добавлена в CI). Новое поверх оценщика EN:

- **Русский счёт слогов — точный:** слог = гласная (а е ё и о у ы э ю я),
  регистр не важен, латинские слова внутри строки — через EN-оценщик, цифры
  слогов не дают. («Подмосковные вечера» = 8, «Ночной эфир» = 4.)
- **Профиль секций `syllableProfile`:** канон тега по базе до двоеточия
  (`[Chorus: fx]` → Chorus), номера снимаются, `Final/Last Chorus` — тоже
  припев с флагом финальности; незнакомые скобки (`[voice raw and visceral]`)
  — ремарки вокала, не текст и не секция; пустые секции не мешают.
- **`singability(lyrics, { bpm })`** — мягкие проверки, все правила вынесены
  в `rules` (пороги видны тестам):
  - **десинк-гарда** (находка «Тысячи окон», продуктовое требование): RU-текст
    + BPM ≥ 150 → предупреждение ДО генерации: английская лирика или темп
    до ~120 BPM, иначе десинк принимается осознанно. EN + 170 — спокойно;
    RU без явного темпа — не паникуем (ничего не выдумываем);
  - **повторяемость припевов:** не-финальные `[Chorus]`/`[Hook]` сравниваются
    дословно; различие → предупреждение хука. Финальный припев с усилением —
    нормальный приём, не предупреждается;
  - **парность куплетов:** Verse 1 ↔ Verse 2 — одинаковое число строк и слоговая
    длина парных строк (грубая дельта ≥ 4 слогов → предупреждение с числами:
    «на повторяющейся мелодии длинная строка спешит, короткая тянет паузу»);
  - сообщение честное: «не вердикт о певучести» (RESEARCH_PACK: без мелодии
    нельзя утверждать певучесть — ловим только грубые расхождения).
- Соблюдение находки №11: модуль НИЧЕГО не дописывает в лирику (нет даже
  поля для «исправленной» версии) — никаких гендер/регистр-инструкций.

### 2. Общий резолв семейства `styleOf` (`studio/music-brain.js`, `2026-11-23-lyrics-1`)

Разметка брекетов (#47) и атмосферное направление автолирики (#48) обязаны
видеть одно семейство — теперь оба зовут `styleOf(text, { style })` (явная
подсказка сильнее, иначе жанровые слова EN+RU; без жанровых слов — null).
Тест проверяет паритет: markLyricsDynamics и styleOf резолвят одинаково.

### 3. Интеграция (`studio/studio.js`, `studio/index.html`)

- **Карточка «Мелодичность лирики»** в createMusic — сразу после карточки
  структуры: singability по лирике (ручной ИЛИ автолирике — простой режим
  тоже не молчит), BPM тем же детектом, что и caption. Мягкая: ничего не
  блокирует, лирику не трогает.
- **Обогащение промта автолирики** — механики ФОРМЫ, не тексты:
  припев дословно слово в слово (все `[Chorus]` идентичны — мелодия припева
  держится ровно); парные куплеты — одинаковое число строк и близкая слоговая
  длина парных строк; строки пропеваемые, рифма естественная, без натуги
  (RESEARCH_PACK: рифма — инструмент, не условие).
- **Атмосферное направление** (эстетика текста → атмосфера трека): семейство
  из черновика сессии или жанровых слов идеи (styleOf) + mood вокального
  профиля семьи (vocal-profile-vocabulary) → одна строка в промт автора
  песен: «Атмосфера трека: nostalgic (synthwave) — образы, лексика и
  настроение текста в этой эстетике». Без жанровых слов строки нет —
  атмосфера не выдумывается.
- `lyrics-brain.js` подключён в index.html (defer, до studio.js), отпечатки
  сборки обновлены (asset-versions, новый build 4c7e3f693d).

## Пример (контрольный прогон)

```
идея: «быстрый джангл 170 BPM, песня на русском» (простой режим, автолирика)
→ detectBpm = 170 → карточка «Мелодичность лирики»:
  «Русская лирика на 170 BPM почти наверняка разъедется с сеткой такта —
   русский текст на быстрых темпах десинхронизирует вокальный кодек модели
   (находка «Тысячи окон»). Надёжнее английская лирика или темп до ~120 BPM;
   иначе десинк принимается осознанно.»

идея: «тёмный synthwave про ночную трассу» (без черновика)
→ styleOf = synthwave, mood = nostalgic → в промт автора песен:
  «Атмосфера трека: nostalgic (synthwave) — образы, лексика и настроение
   текста в этой эстетике.»

лирика: припевы «Припев с ветром» / «Припев с дождём», куплет 2 строкой
вдвое длиннее парной → два предупреждения: хук + слоговая дельта с числами.
```

## Тесты

- `tools/check-lyrics-brain.cjs` — переписан из smoke в полную сюиту (7
  секций): RU-счёт (вкл. ё, регистр, смешанные строки, цифры), профиль
