# Отчёт: студия-агент B — разговорный музыкальный режим + анатомия карточки трека

Дата: 14.11.2026. Сессия: interaction engineer (briix-studio, ветка `feat/studio-agent-b` от origin/main d5832fa).
Вход: `audits/design-collegium-assistants.md` (вариант B + общая анатомия карточки), решение владельца 15.11
(send в music mode = разговор, «Сгенерировать» — отдельная кнопка), дополнение владельца в ходе задачи
(**params.title / params.artist + имя файла скачивания** — «песня — продукт, у неё есть имя и исполнитель»).

## 1. Что сделано

### Разговорный музыкальный режим (ядро B)

- **Dispatch (`create()`)**: music mode, Simple-режим → `createMusicChat(text)` (диалог); «Тонко настроить»
  (advanced) → прежний `createMusic` (Custom-путь сохранён).
- **`createMusicChat`** (новая, по образцу `createChat`): SSE-стрим, отмена через ✕ своей карточки,
  история диалога `session.musicChat.history` (обрезка до 40 сообщений), moderation/лимиты — транспорт
  `chatStream`/`request` тот же. Смерть декорации: **выбранный наставник (Продюсер/Лирик/Автор песни)
  реально получает свой `system`-промпт** + инструкцию формата draft-блока + snapshot полей студии
  (промпт/лирика/инструментал/качество). Смена наставника в music mode сбрасывает историю диалога (АП5).
- **Draft-блок в каждом ответе наставника**: маркер-формат `[briix-draft] {json} [/briix-draft]`, парсинг с
  фолбэком на `BriixProducer.parse` (слабая модель); поля Название/Звучание/Лирика редактируемые,
  кнопки **«Принять в поля»** (бэкап в `entry.backups` + persist до записи полей + revert — паттерн
  `renderProducerDraft`) и **«Сгенерировать трек»** (promptReady-путь: английский промпт черновика уходит
  как есть, без автолирики/перевода/brain-merge; `params.title` из черновика). Self-refine работает:
  «поправь припев» сериями — контекст диалога персистится.
- **Отдельная кнопка «Сгенерировать трек» в композере** (`#genTrack`, music mode, рядом с send) — явная
  генерация текущих полей без диалога.
- «Сделать из этого трек», «Тонко настроить», «Подготовить песню» (producer-путь) — работают как раньше.

### Анатомия карточки трека (общая для ленты и Библиотеки)

- **Обложка = PLAY**: `makeCoverPlayable` — клик по большой обложке запускает/останавливает аудио,
  состояние playing видно иконкой (▶/⏸ поверх обложки), клавиатура Enter/Space, aria-label переключается.
  Нативный `<audio controls>` остаётся fallback.
- **Осциллограмма auto-attach**: `waveform.js` переписан — волна строится сама при появлении плеера
  (без opt-in кнопки), **клик по canvas = seek**, прогресс по волне подсвечен акцентом, прежний range
  оставлен как скрытый клавиатурный a11y-фолбэк (раскрывается по focus-visible). Бюджеты и fallback
  сохранены: 60 c / 8 МиБ / 32 МиБ PCM, серийность декода, закрытие AudioContext при удалении из DOM.
- **Единое меню «⋯»** (`addTrackMenu` + в библиотеке inline): ровно 7 действий — копировать промпт /
  копировать лирику / скачать / повторить с правками / создать обложку / в избранное (с серверным флагом
  infra#77) / удалить (с confirm). Десктоп — dropdown у кнопки, мобайл (≤480px) — bottom-sheet у нижнего
  края. Кнопки-россыпь из карточки трека убраны (осталось PLAY на обложке и «⋯»).
- **Transparency-блок**: «Что уехало в модель» (promptSent + исходная идея) + **Название**, **Исполнитель**,
  **Источник лирики** (наставник/пользователь/автолирика) — всё из `input`.

### Дополнение владельца: песня = продукт

- **`params.title`** в `submitJob`: из черновика наставника, иначе первая осмысленная строка лирики
  (бывший titleSource), fallback `BRIIX track <дата>`; лимит 160, `BriixProducer.sanitize`.
- **`params.artist` = ник пользователя** (`currentUser()` из gate).
- **Имя файла скачивания** `safeFileName()`: «Название - Исполнитель.ext», юникод (кириллица) сохраняется,
  спецсимволы `/ \ : * ? " < > | # % & { } $ ! ' @ + = \`` и серии точек → пробел, краевые тримы,
  пустой результат → `briix-track-<date>`. Применено и к меню «⋯» в ленте, и к скачиванию в Библиотеке.
- **server-contract/README.md**: добавлен пункт «params.title / params.artist — сервер должен писать в
  теги M4A и Content-Disposition», помечено «INFRA-задача выполняется параллельно». Клиент не зависит
  от сервера (поля безопасно игнорируются до внедрения).

## 4. Новые ассерты (гейты из брифа + дополнение)

1. send в music mode **НЕ создаёт джобу** без явного «Сгенерировать» (0 jobPosts после диалоговых ходов);
2. draft-блок содержит «Принять в поля» и «Сгенерировать трек»;
3. наставник реально получает свой system (перехват messages: `/Лирик/`, инструкция draft-формата,
   snapshot полей); self-refine: второй ход несёт историю диалога;
4. «Сгенерировать» из draft = ровно одна джоба, promptReady: промпт наставника не переписывается,
   автоперевод пропущен (0 chatPosts с max_tokens=300);
5. `params.title` = название из черновика, `params.artist` = ник («tester»);
6. диалог и черновики персистятся в session-store (`session.musicChat.history ≥ 4`, feed содержит
   `music_draft`), переживают reload;
7. обложка-клик переключает play/pause (настоящ. WAV в моке), класс `playing` виден на обложке;
8. waveform auto-attach без opt-in (canvas сам), клик по волне = seek;
9. меню «⋯» содержит ровно 7 действий (полный список проверен);
10. transparency-блок: promptSent + Название + Исполнитель + Источник лирики;
11. имя скачивания: `Тест Трек №1 - tester.wav` — кириллица сохранена, спецсимволы (`:`, `/`, `?`) вырезаны;
12. mobile 320×568: bottom-sheet не вылезает за экран (геометрия + отсутствие горскролла);
13. композерная кнопка «Сгенерировать трек» создаёт джобу без диалогового хода, quick-path сборка
    (английский ASCII-промпт) не сломана;
14. check-waveform: auto-attach, canvas click seek, a11y-слайдер, подсветка прогресса, бюджеты/fallback.

## 8. fix restore (баг приёмки владельцем, 14.11 — PR fix/restore-track-card)

**Баг:** после перезагрузки страницы (restore-путь ленты) карточка трека мертва: обложка не кликается,
волны нет, «▶ Слушать» не активирует ничего. Корень: restore-рендер отличался от fresh — обложка не
была PLAY-кнопкой до загрузки файла (клик по ней не запускал load), волна прикреплялась только после

**Фикс (единый рендер-пут: `renderTrackCard` для fresh и restore):**
1. Клик по обложке ДО загрузки = запускает `loadBlob()` и по готовности сразу `play()`

2. **Волна — из серверных пиков (решение владельца 23:18, заменило клиентский декод):**
   карточка при построении запрашивает `GET /files/{id}-peaks.json` (bearer как у /files) и рисует
   волну СРАЗУ — до загрузки аудио, без декода, без бюджетов, трек любой длины (114 с и более).
   Кликовый seek по волне работает и до появления аудио (pending-ratio применяется при setAudio);
   прогресс подсвечивается по audio.timeupdate. Нет пиков (старые треки, 404) — тихий нативный
   плеер, шимер/заглушка убираются, console.warn, никаких сообщений в UI. Клиентский декод

   полностью — «Форма звука недоступна…» = 0 в коде. Контракт peaks.json — в
   server-contract/README.md (INFRA выполняется параллельно).
3. `renderTrackCard(session, { who, job, cover, input, file, loadBlob })` — одна функция для fresh

   осталось, не в скоупе бага).
4. Ассерты: check-studio — restore: волна из peaks.json и PLAY-обложка сразу, `audioRequests === 0`

## 9. fix: markdown-теги секций в лирике (живой кейс владельца)

**Кейс:** GLM-ответы приходят с тегами в markdown (`**Outro**`, `**Verse 2**`) — `latinizeTags`
их не распознавал → карточка «В лирике нет тегов частей» при наличии структуры.

**Фикс (`producer-brain.js`):** новый `normalizeSectionTags(text)` — строка, которая после снятия
markdown (`**x**`, `__x__`, `*x`, `##x` в том числе без пробела) и обрезки целиком совпадает с
именем части (Outro/Verse/Pre-Chorus/Chorus/Bridge/Intro/Куплет/Припев/Пред-Припев/Бридж/Аутро/
Проигрыш/Инструментал/Hook + нумерация «Verse 2», «Куплет 1») → переписывается в канонический
латинский тег. Интегрировано в `latinizeTags` (все точки входа: автолирика, producer-черновик,
музыкальный draft, advanced-поля) и в `structureWarnings` (markdown-теги = структура, «нет тегов»
не выдаётся). Ремарки-скобки в теле лирики (`[voice raw and visceral]`, `(шёпотом)`) и inline-
markdown строк НЕ трогаются — валидны для ACE-Step. Неполный каркас — предупреждение, как раньше,
без автодобавления.

**Ассерты (check-assembly):** `**Chorus**`/`**Outro**` → `[Chorus]`/`[Outro]`; `__Verse 2__`,
`##Припев`, `*Outro`, «Куплет 1» → канон; `[voice raw and visceral]` и `(шёпотом)` сохранены;
markdown-каркас → предупреждение о структуре есть только про отсутствующие Verse/Chorus.

**Сюиты:** assembly, producer, studio (49), peaks-waveform, session-store, studio-storage — PASS.
