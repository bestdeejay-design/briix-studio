# Задача briix.ru#109 — чистая сборка промпта и лирики + brain-ступень + языковое правило

Ветка `feat/assembly-109` репозитория **briix-studio** (студия вынесена из briix.ru).
Прод-деплой — автоматически через deploy-stand после merge (ручного деплоя нет).

## Что сделано

### 1. Brain-ступень (детерминированный мозг DJ1) — обязательный этап сборки
- **`studio/music-brain.js` (новый)** — перенос детерминированного мозга из
  PR briix.ru#85 (`music-brain.js`, ветка `feat/music-brain`, коммит c20005a8),
  источник правил сохранён в шапке (dj1/brain · prompt-rules + style-taxonomy,
  срез 2026-11-14). Студийные адаптации (задокументированы в шапке файла):
  - дефолт языкового тега лирики — `English lyrics`, а не `Russian lyrics`
    (языковое правило владельца 15.11: отсутствие указания ≠ русский);
  - BPM не выдумывается: тег ставится только если темп задан в идее или формой
    (продюсер-канон «не приписывай конкретный темп»); новый `detectBpm()`
    распознаёт «72 BPM», «90 ударов в минуту», «120 уд. в мин»;
  - экспорт `globalThis` (студия и vm-тесты без window).
- Теги: ≤ 240 симв., порядок жанр → инструменты → вокал → BPM → настроение →
  эпоха → продакшн; негативы перефразируются позитивно
  («без кульминации» → `flat dynamics, loop-like`, «без реверберации» →
  `dry close-mic production`, «без женского вокала» → `male vocals only` и т.д.).
- `buildLyricsSkeleton` — каркас [Intro]→[Verse]→[Pre-Chorus]→[Chorus]→[Bridge]→[Outro]
  с каноническими латинскими тегами.

### 2. Sanitize и языковое правило — `studio/producer-brain.js`
- Новые чистые функции (экспортируются в `BriixProducer`): `sanitize`,
  `stripMarkdown`, `stripServiceBoilerplate`, `isAsciiOnly`,
  `detectExplicitLanguage`, `latinizeTags`, `structureWarnings`,
  `translateMessages`, `validTranslation`.
- `sanitize` снимает **только** markdown-обрамление (`**`, `_`, бэктики,
  заголовки, обрамляющие кавычки) и служебные обёртки («Конечно!», «Вот ваша
  песня:», «Я подготовил…», «Here's your song:»); художественный текст и смысл
  не трогает. Регресс на живом факте владельца:
  `**"Глубокий, динамичный ритм с мощным басом…` → `Глубокий, динамичный ритм с мощным басом…`.
- `latinizeTags` переписывает ТОЛЬКО теги частей ([Куплет 2]→[Verse 2],
  [Припев]→[Chorus], [Пред-Припев]→[Pre-Chorus], [Интро]/[Вступление]→[Intro],
  [Бридж]→[Bridge], [Аутро]/[Концовка]→[Outro] и lower-case английские варианты
  к канону); незнакомые теги не трогаются.
- `detectExplicitLanguage`: «на русском», «по-русски», «in russian», «на
  английском», «по-английски», «in english», «на французском», «in french» →
  явный язык; отсутствие совпадения → null (не «русский»).
- System-промпт продюсера обновлён: prompt — ТОЛЬКО по-английски; лирика —
  на явно указанном языке, иначе по-английски; теги секций всегда латиницей,
  адаптивный каркас. Прежний канон («не приписывай конкретный темп») сохранён.

### 3. Конвейер сборки — `studio/studio.js` (`createMusic` + `autoLyrics` + `translatePrompt`)
- `Сборка`: исходная идея сохраняется неизменной (`rawIdea` → карточка,
  журнал, библиотека, `input.prompt`); sanitize убирает markdown/служебное;
  brain-теги (`BRIIX_MUSIC_BRAIN.buildTags`) — обязательная ступень.
- Prompt в модель (`submitJob`, `params`): 
  - advanced + ASCII (пользователь/продюсер уже собрали английский) → поле как есть;
  - не-ASCII идея (например русская) → связный английский перевод через
    producer-чат (`translatePrompt`, non-stream, `max_tokens: 300`, abortable
    по ✕ карточки, потолок 60 с) + добление недостающих brain-тегов;
    при неудаче перевода — brain-теги как гарантированный минимум
    (болтовня/JSON/markdown/не-ASCII ответы отбраковываются `validTranslation`);
  - быстрый путь с ASCII идеей → `mergePromptTags` (добавляются только
    недостающие brain-теги); только лирика → промптом остаётся она.
- `input.promptSent` — ровно то, что уехало в модель; карточка «Промпт и текст
  песни» показывает обе версии («Промпт в модель» + «Исходная идея») —
  прозрачность по правилу 4 владельца. Повтор подставляет исходную идею.
- Лирика: sanitize + `latinizeTags` на границе поля→params; для ручной лирики —
  `structureWarnings` → карточка-предупреждение (не навязывать); автолирика —
  новый system-промпт: дефолт английский, явное «на русском» уважается,
  обязательный адаптивный каркас с латинскими тегами.
- Инструментал: флаг + brain-тег `instrumental`, лирика не отправляется.

### 4. Producer-карточка
- В черновике продюсера появляется провенанс «Теги ACE-Step (brain): …» из
  исходной идеи; prompt-поле остаётся английским текстом LLM (принятие в поля
  и повторное использование не ломаются).

### 5. Regression-сюита `tools/check-assembly.cjs` (новая, vm, без браузера)
Покрывает пункты задачи и дополнение владельца:
- (а) русская идея → POST prompt ASCII/английский;
- (б) без указания языка → лирика английская (дефолт);
- (в) «…на русском» → языковой тег русской лирики, промпт всё равно английский;
- (г) теги частей всегда латиницей, текст не трогается;
- (д) sanitize на живом факте владельца (`**"Глубокий…`);
- (е) ручная лирика не заменяется (только латинизация тегов + предупреждение);
- (ж) instrumental — без лирики, с флагом и brain-тегом;
- (з) болтовня модели не утекает (обёртки снимаются, не-ASCII/JSON-ответы
  перевода отбраковываются);
- (и) русская идея → английские ACE-теги таксономии в промпте, ≤ 240 симв.;
- (к) «без кульминации» → `flat dynamics` (+ «без реверберации» →
  `dry close-mic production`);
- (л) BPM из идеи попадает в теги;
- (м) отсутствие указания языка → `English lyrics` (brain + system продюсера +
  автолирика в studio.js — проверка исходника).

### 6. check-studio.cjs — новые ассерты (сюита ослаблена? НЕТ: 46/46 PASS)
- Быстрый путь (тест 17): русская идея → POST prompt ASCII, ≤ 240, содержит
  `vocals` и `English lyrics`, без `duration`/`duration_seconds`; болтовня
  заглушки («Стрим пришёл…», «УЛУЧШЕННЫЙ ТЕКСТ») не утекает; факт вызова
  перевода через producer-чат (`max_tokens: 300`, system `Output ONLY the
  English prompt`).
- Тест повтора («Повторить с правками»): исходная идея подставляется в поле
  для правки, а в POST уходит английская сборка — ожидание ассерта адаптировано
  под новый контракт (заглушке задан английский перевод), намерение старого
  ассерта («повтор отправляет отредактированный текст») сохранено. Старые
  ассерты не удалялись.
