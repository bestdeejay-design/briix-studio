## 7. Риски и правила

1. **Строки едут** (PR #16 уже сдвинул все ссылки аудита; каждый следующий PR тоже будет) — правки по именам функций, номера в этом плане — снимок на `a9bed11`.
2. **Самый рискованный кусок — R2/R3:** перестройка рендера сразу после того, как PR #16 его перестроил. Обязательны: замер A11 до/после, скриншот-сверка (`audits/screens-audit/capture.cjs` из PR #17), сюжет «500 треков». Если R3 не даёт эффекта по замеру — откат, а не дотюнивание.
3. **axe (T-45) — строго после 3.4**, иначе CI красный на известных нарушениях.
4. **PR #17 не мержится** — только реестр; errata из §1 занести в issue #15.
5. **Маленькие PR** ≤ ~300 строк; каждый несёт ассерт (T-46), а перфоманс-находки — замер до/после.
6. **Контрактный хвост (T-07/T-11/T-12) не начинать до ответа INFRA** — половина из них серверные, клиентская часть без сервера не проверяется.
7. **Не дублировать PR #16:** библиотечный рендер уже перестроен в `buildTrackCard` — R2 сводит ветки к одному входу, а не переписывает библиотеку заново.
