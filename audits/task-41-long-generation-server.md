# Поставка: #41 (хвост) — длинные генерации доезжают, сервер перестаёт ошибаться «на каждый чих»

**Ветка:** `work/41-long-generation-server` · **База:** `origin/main` (02ba84d)
**Задача:** briix-studio#41, продолжение волны владельца 21.11 («сначала вывод в чате + сервер, потом мозг»).
**Связанная:** fix(#41) cce2f1e (PR #44) — read-only черновики, стриминговая загрузка, карточка без ожидания блоба. Эта ветка НЕ дублирует её: закрывает то, чего в cce2f1e не было — потолок ожидания генерации, серверные таймауты GLM, предсборку M4A и ложные блокировки модерации.

## Что сделано

### 1. Поллинг длинных генераций: потолок 60 минут и «задача жива» вместо ошибки

- `createMusic` и `resumeWaitingJob`: для музыки `timeoutMs` 40 → 60 минут
  (серверный бюджет vocal CPU — 2400 с = 40 мин — плюс очередь и обложка;
  прежний общий потолок 40 мин совпадал с бюджетом сервера и рвался ровно
  на длинных генерациях). Фото — прежние 40 минут.
- По истечении потолка задача на сервере ЖИВА (запись в `session.jobs`
  не снимается): вместо мёртвой `errorCard` — notice «Задача всё ещё
  выполняется на сервере… Трек появится после перезагрузки страницы или
  в Библиотеке». Перезагрузка подхватывает результат через `resumeSessionJobs`.

### 2. Сервер (bff.py) — три корня «ошибки на каждый чих»

- `GLM_TIMEOUT_NONSTREAM = 180`: непотоковый GLM-вызов (продюсерский черновик,
  1800 токенов) физически длиннее минуты — прежние 60 с резали его на
  502 upstream_error. SSE-путь — прежний sock_read 60 с. Клиентский таймер
  «Подготовить песню» поднят 150 → 210 с, чтобы успеть дождаться честный ответ.
- `_prebuild_m4a`: M4A собирается фоном сразу после `ready` музыкальной джобы —
  кэш тёплый к первому GET `/files/{id}`. Дополняет стриминговое окно первых
  байтов (90 с) из cce2f1e: ffmpeg на длинном треке мог не успеть за окно,
  теперь обычно уже собран; mux-on-download остаётся страховкой.
- Модерация: `SEXUAL_TERMS` ловил `гол[аоу]\w*` — «голос», «голоса»,
  «голубой», «голод». Вместе с `MINOR_TERMS` («детск…», «школьник», «дочк…» —
  ностальгические темы песен) это давало мгновенный 422 «explicit» без
  LLM-ступени: «детская площадка, голубое небо» блокировалась. Теперь
  матчатся только формы прилагательного «голый»; бонус — множественные
  формы («голых», «голые», «голым»), которые старое правило пропускало.

### 3. Карточка трека: «Что уехало в модель» тем же языком чтения, что черновики

`addMusicDetails` — достройка паттерна #41 из cce2f1e до карточки трека:
мета-блок (Название / Исполнитель / плашка «Промт собран мозгом: N слоёв»
акцентом / Источник лирики) + отдельные `draftReadRow`-строки «Промпт в
модель», «Исходная идея» (когда есть) и «Текст песни» — разворачиваются,
копируются целиком; редактируемых полей в карточке нет. Правило
`.track-details div` скоуплено до `.track-meta div`, чтобы не красить
внутренности строк чтения.
