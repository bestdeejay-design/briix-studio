## Что сделано (по W1-1…W1-5 спеки с правками П1–П3)

### W1-1. Schema v2 + миграция в точке загрузки (`studio/session-store.js`)
- `SCHEMA_VERSION = 2`; `migrateV1toV2(profile)` (+ экспорт в `BriixSessionStore`):
  - merge `musicChat.history` в КОНЕЦ общего `session.history` с пометкой элементов
    `via:'music-chat'` и `assistant`; служебный маркер-граница `{role:'system',
    content:'Муз-диалог перенесён из предыдущей версии'}` — в контексте, не рендерится;
  - `session.assistantId` из `musicChat.assistant` (fallback `mentor`);
  - `draft.quality` (дефолт flash), `draft.instrumental` (из первого трека сессии, fallback false);
  - `draft.styleFamily` осознанно не восстанавливается (в v1 жил на DOM);
  - `musicChat` удаляется, `revision` +1. **Лента (`feed`) не мигрируется никогда** (П2).
- Миграция идемпотентна; гейт: `schemaVersion ≥ 3` → `schema_unsupported`.
- Тот же путь для локального fallback-бэкенда (запись мигрированного профиля обратно).
- `sanitizeSession` дополнен: `music_draft.backups` (P3-1), неизвестная `assistantId` →
  mentor, `draft.styleFamily` не-строка → удалить, `quality` → flash, `instrumental` → boolean.

### П1. Смешанные вкладки — явный отказ, не тихая потеря (`studio/studio.js`)
- `persistSessions`: коды `invalid_profile`/`schema_unsupported` выделены из общего
  warnStorage-пути: ретраев нет, несохранённое сериализуется в
  `localStorage['briix-studio-pending-v1-<nick>']` (JSON-снапшот + `capturedAt`),
  показывается блокирующий баннер «Приложение обновлено. Сохранения остановлены —
  обновите страницу. Ваш текст не потерян» с кнопками «Обновить»/«Скопировать данные».
- `startSession` → `restorePendingV1()`: до миграции проверяет pending-ключ,
  предлагает «Восстановить несохранённое», вливает сессии через тот же tolerant-
  пайплайн (дедуп по id), ключ удаляется после ответа (включая протухший >7 дней).

### W1-2. Один чат со сменой наставников (`studio/studio.js`, `studio/index.html`)
- Табы `chat|photo|music` → два фокуса: **«Создание музыки» (дефолт)** и **«Фото»**.
- Единый реестр ролей `CHAT_ROLES` = 7 универсальных наставников + 3 музыкальные;
  чип наставника переключает роль ВНУТРИ диалога; смена роли НЕ обнуляет историю,
  в ленту пишется системная карточка «Роль переключена».
- `createMusicChat` удалён: `createChat` — единый поток `session.history` (срез −80),
  system = роль + draft-инструкция + снапшот полей; ответы с draft-блоком рендерятся
  карточкой `music_draft`, без — обычной карточкой диалога с «Сделать из этого трек».
- «Подготовить песню» — действие роли Продюсер в том же диалоге; занятость
  унифицирована: `sessionBusy` (chat|producer|photo|resume) вместо `sessionBusy`+`producerRequests`.
- `assistantId` — свойство сессии (P2-1); статус «Работаем…» горит только от операций
  активной сессии; `improving` — на сессию.
- Старый аудит `audits/audit-music-mode-interaction.md` помечен устаревшим.

### W1-3. Сессионное состояние полей (P1/P2-2/P2-3/P2-4/P3-2 аудита)
- `styleFamily`: `session.draft.styleFamily` вместо `dataset` на DOM; бейдж
  «стиль: <семейство>» рядом с полем; ручная правка поля снимает подсказку;
  `createMusic` читает из сессии — генерация в сессии B больше не наследует стиль A.
- `quality`/`instrumental` — в `session.draft` (переключение чипа/тумблера пишет
  draft активной сессии; localStorage остаётся дефолтом только НОВОЙ сессии).
- `pendingDraftTitle` на сессии удалён: название уходит в генерацию только явным
  действием карточки («Сгенерировать трек» → ctx.title).
- `repeatOf` на сессии заменён на `pendingRepeats` (Map по id сессии, in-memory,
  потребляется следующим запуском этой сессии).
- `fileBlob`: allow-list query — `?refetch=1` на `/files/{id}.m4a` разрешён (P3-2),
  остальные query/hash по-прежнему `unsafe_url`.

### W1-4. Экспорт v1 (честные ограничения)
- Меню «⋯» карточки трека (лента и Библиотека): «Скачать аудио (M4A)» (как раньше),
  «Скачать WAV — мастер без тегов» (GET /files/{id}.wav; пока бэфф не отдаёт —
  честная ошибка, без фейков), «Скачать обложку» (/files/{id}-cover.png или cover_url).
  MP3-пункта нет до правок бэффа (волна 2/инфра).
- `mediaFileName(…, variant)`: расширение по ЗАПРОШЕННОМУ варианту (дизамбиг extOf).
- П3: у каждой карточки трека — блок обложки со статусом; готовый трек без cover_url
  получает видимую плашку «Обложка не сгенерировалась — генерация не удалась на
  сервере» (без мёртвого ретрая — ретрай-эндпоинта на сервере нет, честная плашка).

## Открытые вопросы координатору (не выдумано — зафиксировано честно)
1. **Маркер merged-истории**: спека описывает role-метку элементов `{...msg, role:
   'mentor'|'producer'}` — но `role` в `history` уже занят LLM-ролью (user/assistant);
   перезапись сломала бы контекст. Реализовано как `via:'music-chat'` + `assistant`.
   Подтвердить, что такая трактовка принимается (или оформить правку спеки).
2. **Восстановление pending-v1 при совпадающих id**: если v2 уже мигрировал те же
   сессии, restore вливает только новые id (дедуп). Кейс «часть сессий новее» не
   различается — считаем допустимым для волны 1, при замечании ревьювера усилю.
3. **Новый долг компоновки (волна 2-кандидат)**: композер музыкального фокуса
   выше старого чат-композера. На 320×568 тулбар (vocalSeg + чипы) переносится на
   3 ряда, композер ~470px, окно ленты сжимается до полоски (~28px). Смягчено
   минимально: «Новый чат» на ≤480px сжат до иконки ＋ (≥44px тач-таргет),
   подсказка Enter скрыта на ≤480px (решение о полной компоновке узкого
   музыкального композера — дизайн-вопрос владельцу, не делался самовольно).
   Сценарий сюиты «ленивая загрузка 100 фото» переведён на десктоп-вьюпорт
   (инвалидация ленты по видимости — механика не менялась).
4. **Мок-детекция ролей в check-studio**: контекст студии содержит слово «Лирика:»,
   старый регекс `/Лирик/` ложно отправлял наставника в draft-ветку. Детекция
   ужесточена до `Ты «(Продюсер|Лирик|Автор песни)»|музыкальный продюсер BRIIX`
   (последнее — system producer-brain для prepareMusic).
